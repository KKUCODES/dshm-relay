# Remote 大响应分块

状态：2026-10-23 独立 `fix/remote-response-chunks` 分支实现与本地验收完成，协议提交 `94183d0` 已推送；App preview.7与插件0.1.87已公开发布。公共中转升级尚待服务器登录信息，未宣称公网分块已生效。只修改 DSHM 手机端、插件与中转，不修改 DSH。实现：[KKC-75](https://linear.app/kkcodes/issue/KKC-75)；发布与部署：[KKC-76](https://linear.app/kkcodes/issue/KKC-76)。

## 用户可见行为

首次打开聊天、加载更早历史和实时接收长输出，超过单帧大小时自动分块。手机先验证并还原完整逻辑消息，再交给原聊天模块；不截断工具输出，不改变官方历史分页规则。断线、取消或撤权丢弃半份数据，重新连接沿用原只读订阅恢复流程，写操作不自动重发。

仅提高单帧上限会把压力转移到中转、原生桥和手机内存；仅减少历史条数不能处理单条大事件。本实现保持单帧 2 MiB 上限，在外层增加有界传输。

## 协商与兼容

通信大版本仍为 protocol 1 / remoteTransport 2，额外能力为 `responseChunksVersion: 1`。

1. 新插件连接 Host WebSocket 时发送 `x-dshm-response-chunks: 1` 请求头；URL 仍只有既有 `transport=2`，兼容旧网关的严格查询字段检查。
2. 新中转在手机 `ready` 消息中宣告能力；插件在 `remote.negotiate` 结果中宣告同一能力。
3. 新手机只有在两者均宣告后，才给请求附加 `responseChunks: 1`。权限、端点、设备和连接归属仍由原网关检查。

| 组合 | 行为 |
| --- | --- |
| 三端均支持 | 小响应保持原帧，大响应使用分块 |
| 任一旧端 | 保持旧格式与 2 MiB 上限，超限明确失败 |
| 新中转＋旧插件却收到显式分块请求 | 返回 `response_chunks_unavailable`，不转交不支持的宿主 |

现有公网服务并未升级。本修复生效需要三端配套更新；旧版本“可继续小响应通信”不代表旧端也能打开超限内容。

## 帧与边界

| 类型 | 字段与职责 |
| --- | --- |
| `responseStart` | 原请求 `id`、独立 `transferId`、`kind: result/event`、UTF-8 `bytes`、完整值的 `sha256` |
| `responseChunk` | 同一身份、连续 `index`、最多 64 KiB 原始字节的规范 base64 |
| `responseAck` | 手机存入对应片段后，确认同一身份与连续 `index` |
| `responseEnd` | 所有字节和确认齐备后，结束这一条逻辑消息 |

中转沿原请求映射 `id`，校验 Host、设备连接、顺序、块长、窗口和声明预算，只保存计数与路由，不重组正文。手机另外校验 SHA-256、UTF-8 与 JSON，校验成功前业务层拿不到半份内容。四块滑动窗口限制在途片段；发送端等待确认，业务流等待写入完成，避免无限读取上游。

- 单条逻辑值最多 32 MiB；每连接最多 4 条在途重组，声明字节合计最多 64 MiB。
- 电脑待发送序列化消息合计最多 64 MiB；手机已完成事件队列另外共享 64 MiB / 每流 256 项上限。
- 上述为序列化字节预算，不是 JavaScript 堆内存承诺；解析对象、字符串及临时编码仍有额外开销。
- 空闲 30 秒、单条总时限 120 秒；取消、关闭、撤权及错误释放资源和原订阅。未实现跨断线断点续传，重连重新读取。
- 单独的响应确认限速 4096 次/秒，不挤占原普通请求 120 次/秒与文件/上传确认 512 次/秒。
- 既有文件/上传分块接口保持原合同；这次增加的是通用 RPC 结果和流事件分块，不放开任意 URL、权限或本地文件范围。

## 复验

共享源码：[序列与重组](../packages/protocol/src/response-chunks.ts)、[网关路由](../packages/gateway/src/hub.ts)。真实 HTTP/WS 跨仓库联调在 [response-chunks.test.ts](../tests/response-chunks.test.ts)，其 DSH 业务 Gateway 与聊天内容为合成夹具，配对、鉴权、中转、Relay、手机传输均为实际实现。

`npm run build`；`npm test -- --exclude tests/latest-host.test.ts`。后者排除缺失旧本体补丁夹具的历史测试，不补装补丁、不把该测试算通过。PostgreSQL和其他按条件跳过的专项仍按原环境要求执行。

原官方 rc.2 CLI＋自有插件＋生产中转＋Android 专用 UID 使用 [隔离协调器](../scripts/verify-rc21-host.mjs)和 [原官方持久化夹具](../scripts/seed-large-history.mjs)：设置 `DSHM_CHECK_LARGE_HISTORY=1` 后，创建 60 回合合成聊天，尾部页和更早页各含大消息。不调用模型；启动前经原 `session/page` 验证夹具有效且超过 2 MiB。手机脚本设置 `DSHM_ANDROID_SERIAL` 选择专用设备；失败记录与成功记录分开保留。

发布顺序：先提交并推送这次后端协议，再将 App 与插件的 `ci/release.json.backendCommit` 固定到该提交，重建插件 `lib/` 回执，运行两端 CI。App preview.7与插件0.1.87配套提供本修复；不能用旧协议固定值构建新发行。生产升级保留数据库、设备授权和现有服务器配置；实际部署状态见[公共服务器运维](../deploy/public-server.md)。
